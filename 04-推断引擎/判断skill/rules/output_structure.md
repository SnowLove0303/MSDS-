# Word 输出结构模板（msds_docx.py 渲染依据）

> content.json 必须包含以下键。
> - 格式示例：`templates/content.example.json`（最小可渲染骨架）
> - **质量基准（黄金范例）**：`templates/os1330-full-example.json` —— OS-1330 完整 16 节推导方案，
>   每次交付应达到同等级详实度（16 节齐全、每节含【原文问题】+【规范应写内容】、含诊断表/依据/参考）。
> - 自动骨架：`scripts/build_initial_content.py` 从 facts.json 生成 16 节完整初稿，AI 再逐节完善。

## content.json 键结构
```json
{
  "title":   "封面大标题（黑体18pt，方案用）",
  "sds":     {"product":"产品名","company":"供应商","date":"修订日期","first_date":"最初编制日期",
              "sds_no":"SDS编号","version":"版本","basis":"编制依据"},   // 纯MSDS封面用
  "meta":    ["元信息行…"],                 // 封面下：推导对象/依据/日期
  "overview":["任务概述段落…"],              // 一、任务概述
  "diagnosis_header": ["部分","原文存在问题","严重程度"],
  "diagnosis_rows":   [["S1 物料及供应商标识","问题…","中/高/低"], …],  // 一、1.1 诊断汇总表
  "basis_blocks": [
      {"title":"2.1 标准与规范依据","items":["…"]},
      {"title":"2.2 混合物危害组分浓度限值","items":["…"]},
      {"title":"2.3 产品身份依据（第1部分）","items":["…"]},
      {"title":"2.4 成分依据（第3部分）","items":["…"]},
      {"title":"2.5 理化性质依据（第9部分）","items":["…"]},
      {"title":"2.6 组分危害数据（联网检索）","items":["…"]}
  ],                                        // 二、推导依据（块可增删）
  "sections": [
      {"num":"第1部分","title":"化学品及企业标识",
       "diagnosis":"原文问题…",
       "content":["规范应写内容行…"]},
      … // 16 节都要有
  ],
  "references":["参考资料…"]                // 四、参考资料
}
```

## 标准写入版（第三份交付：精简·命令式 content + `--pure` 渲染）

推导详实版（方案 content）和**标准写入版**（`content_<产品>_write.json`）是两种详略形态：

| 形态 | 用途 | 内容风格 |
|---|---|---|
| 推导详实版 `content_<产品>.json` | 方案 Word / 原始正文 | 大段完整论述，含判据解释、数据出处、多组分并列 |
| **标准写入版 `content_<产品>_write.json`** | 标准 MSDS 正文（可直接写入模板） | **每条值 1-3 个短句、命令式祈使句、要点式** |

**标准写入版写作铁律**（对标 `PEA-4139 MSDS_CN 冠志 模板.docx`；注意"简洁"≠"偷懒/笼统"，
每条值要有实质内容，缺失信息用"无数据/不适用"，切勿用大而化之的一句话应付）：
- 每条字段值 1-3 个短句，动宾/祈使句开头（"立即脱去…""禁止排入…""戴防护设备…"）；**多句之间用 `\n` 换行**（渲染为同一单元格内分行，对齐模板）。
- **S1 对齐模板字段**：只写 1.1产品名称 / 中文名称 / 化学品分类 / 1.2产品使用建议和使用限制（推荐+限制合并一行）/ 1.3供应商信息 / 供应商名称 / 供应商地址 / 电话 / 传真。
  **不得包含** 英文名称、邮政编码、电子邮件、应急咨询电话、SDS编号、版本、最初编制日期（这些进封面 sds 键，不进 S1）。
- **S2 象形图**：`{"t":"pictogram"}` 条目紧跟在"象形图："字段后，渲染器自动把图片嵌入该字段值列（S14 的 TDG 标志作合并行）。
- **S8 完整范式**（对齐模板）：8.1 暴露控制 → 职业接触限值表 → 呼吸系统防护 → 手部防护 → 防护手套的合适材料（氟化橡胶-FKM / 丁基橡胶-IIR / 丁腈橡胶-NBR 三种，含厚度与穿透时间）→ 建议 → 眼睛防护 → 身体防护 → 生物限值表（组分/标准来源/生物监测指标/生物限值/采样时间）→ 8.3 工程控制。
- **S11 用真实毒理研究资料**，不得用 GHS 分类替代：按组分写 物种/途径/剂量/结果（如"三亚乙基四胺：大鼠经口 LD50 约2.5 g/kg；兔经皮 LD50 805 mg/kg"），刺激性写动物试验（兔皮肤腐蚀 1B、兔眼损伤）、致敏写豚鼠试验、致突变写 Ames/OECD 试验结果。数据来源：PubChem、ChemicalBook、ECHA。
- **S12 同样搜集真实生态研究资料**：鱼类/蚤类/藻类 LC50/EC50（含暴露时间、物种）+ 28天降解率 + BCF/log Kow，不写"对水生生物有害"这类分类结论代替。
- **S14 写具体要求而非标准代号**：14.1-14.3 各运输方式写运输规则（如 JT/T 617、IMDG、IATA DGR）+ UN号/类别/包装组 + 装运要求；14.4 写 温度范围/远离物/防泄漏/应急处理等具体操作要求。
- **S16 免责声明复用模板长文**："就我们所掌握的知识信息，截止本安全技术说明书发布之日，它提供的资料是正确的。所提供的信息仅仅作为安全处理、使用、生产、储存、运输、处置和排放的指导书，而不是一份担保或品质说明书。本资料只针对所指定的具体物料，而对这种物料与其它物料混合使用或在其它制程中使用的情况，则未必有效（除非在文本中有特别说明）。"
- 各节字段显示名**保留标准序号**（1.1、2.1、9.6、11.1…），content 里字段名尽量与 `sds_structure.json` 显示名一致，避免序号丢失或兜底显示。
- 生成方式：单独写一份精简 content（如 `build_<产品>_write.py`），再 `--pure` 渲染，
  文件命名 `<产品> MSDS标准写入版.docx`。

## 纯 MSDS 正文的表格化渲染（`--pure`，对齐标准模板）

`--pure` 输出按**标准 MSDS 表格结构**渲染（对标 `PEA-4139 MSDS_CN 冠志 模板.docx` 的 16 表结构），
页眉含 产品名称/SDS编号/修订日期，页脚"第 X 页 共 Y 页"，A4 边距 2.0cm。结构如下：

| 区块 | 渲染方式 |
|---|---|
| 封面 | 4 列表格：产品名称\|值\|编制依据\|值；下行 修订日期/最初编制日期/供应商/SDS编号/版本 等（来自 `sds` 键，含 `first_date`） |
| 第 1~16 节 | 2 列表格：表头 = `{num}.{title}`（如"1.物料及供应商标识"，深蓝 1F4E79 白字），行 = 字段名\|值 |
| 成分表（S3） | `{"t":"table"}` 子表：主表后另起 表头 + 数据行（表头浅蓝 DCE6F1） |
| OEL 表（S8） | `{"t":"table"}` 子表（组分/标准来源/类型/标准值/备注） |
| 法规信息（S15）/其他信息（S16） | **单列表格**：表头 + 每条内容一行（对齐模板） |
| 象形图（S2/S14） | `{"t":"pictogram"}` 嵌入图片行（1.6cm） |

### 字段名匹配机制（sds_structure.json 别名）
`templates/sds_structure.json` 定义每节的标准字段（对齐模板），每个字段可为 `"显示名"` 或
`["显示名","别名1",...]`。渲染时把 content 的 `"字段名：值"` 行按字段名**全等匹配**到标准字段：

- 匹配成功 → 显示标准字段名（如 content 写"闪点：>94℃"→ 显示"9.6 闪点"）；
- 不匹配 → 兜底显示原字段名（如"防止次生灾害"）；
- **缺项策略**：S9（物理化学特性）缺项填"无数据"、S14（运输）填"不适用"、其余节跳过。

> 写 content 时尽量让 `"字段名"` 与 `sds_structure.json` 的别名一致（如"外观性状"→9.1外观、
> "pH值"→9.3、"熔点/凝固点"、"闪点"、"固体含量"等），可减少兜底显示、保证字段对齐模板。
> 别名有重复会造成同一内容渲染两次（已自动去重，但写结构时仍应避免）。

### content 条目类型（表格化渲染时的处理）
| 写法 | 表格化处理 |
|---|---|
| `"字段名：值"` | 主表 2 列行（字段名\|值） |
| `"整段描述…"`（无字段名冒号） | S15/S16 归入单列列表行；其余节整行合并显示 |
| `{"t":"table","label","header","rows"}` | 子表（S3 成分、S8 OEL） |
| `{"t":"pictogram","code":"GHS05"}` | 图片行（S2 用 GHS 危害象形图、S14 用 TDG 运输标志） |
| `{"t":"note","text":"…"}` | 剔除 |

## 内容条目区分：可写入 MSDS vs 仅说明（每次交付必做）
`sections[].content[]` 的每个元素必须是以下两种之一，以支持"方案 Word + 纯 MSDS 正文"双输出：

| 写法 | 含义 | 在方案 Word 中 | 在纯 MSDS Word 中 |
|---|---|---|---|
| `"可直接进SDS的正文…"` | 可写入 MSDS | 正常宋体显示 | **保留** |
| `{"t":"msds","text":"…"}` | 可写入 MSDS | 正常宋体显示 | **保留** |
| `{"t":"pictogram","code":"GHS05"}` | GHS 象形图图片 | 嵌入图片（2cm） | **保留（嵌入图片）** |
| `{"t":"note","text":"…"}` | 仅说明 | 灰色楷体 +【说明】前缀 | **剔除** |

**象形图（pictogram）**：`code` 取两套之一，渲染时从技能 `templates/pictograms/` 目录取 PNG 嵌入 Word：
- **GHS 危害象形图**（GB 30000 系列 9 个）：`GHS01`~`GHS09`。S2 的象形图应按产品分类
  逐个列出（如皮肤腐蚀1B → GHS05 腐蚀；皮肤致敏1/急性经口4 → GHS07 感叹号；水生3 → GHS09 环境）。
- **运输标志（TDG）**（《危险货物运输建议书》）：`TDG1.1`/`TDG2.1`/`TDG3`/`TDG4.1`/`TDG5.1`/`TDG6.1`/`TDG8`/`TDG9`。
  S14 运输信息对危险货物（如第8类腐蚀性）应嵌入对应运输标志（如 UN 2735 第8类 → `TDG8`）。

象形图属于"可写入 MSDS"，方案 Word 与纯 MSDS 输出同样嵌入。缺失图片时回退为文字标注。

**属于 note（仅说明，不进纯 MSDS）的内容**：
- 推导理由/判据解释（如"说明：本品各成分含量处于1%~5%区间，经评估不构成…"）；
- 括号里的编辑指令（如"（建议设置专用公共邮箱）""（如无中国限值，注明未建立，可参考ACGIH）""（如产品需库房管理时填写）"）；
- 字段提醒、"参见第X部分"、待完善标记（build_initial_content 生成的【待推导】【需补充】【必填字段】均自动标为 note）。

**属于 msds（可直接写入 SDS）的内容**：描述、数值、措施、法规条目、标签要素、毒理数据等规范正文。数据行里如果整行混有括号说明，应把括号说明拆成独立 note 条目（参见 `templates/os1330-full-example.json` 的拆分示范）。

> 打磨原则：看到括号里"建议/应/可/填写/参考"这类给编写者的提示，就拆成 note。

## 与覆写引擎的对接（标准化表格版 MSDS）
推导方案的"纯 MSDS 内容"最终经覆写引擎落到标准 16 节表格模板，产出 `<产品名> 标准化输出.docx`：
```
content.json（含 msds/note 区分）
   → 生成写入项 write_items_*.json（label/value，需按模板字段映射）
   → clean_write_items.py（覆写引擎，剔除 note 内容）
   → write_items_*_pure.json
   → msds_overwrite_engine.py --write-items 纯版 → 标准化输出（纯 MSDS，无说明）
```
`clean_write_items.py` 的 note 剔除规则与本表一致（删"说明：…"整段、删括号编辑指令、
个别括号保留有用信息如"（低于-5℃有冻结风险）"）。改 note 拆分规则时同步更新该脚本。

## 每节 content[] 的必填要点（对照 SKILL.md 铁律表）
- **S1**：中英文名 / 商品名 / 产品类型 / 推荐+限制用途 / 供应商全信息（名称/地址/邮编/电话/传真/邮箱/24h应急电话）/ SDS编号/版本/最初编制日期/修订日期。
- **S2**：紧急情况概述 / GHS危险性类别 / 标签要素（象形图/信号词/危险性说明/防范说明）/ 物理和化学危险 / 健康危害（吸入/皮肤/眼睛/食入/慢性）/ 环境危害 / 其他危害。
- **S3**：产品类型=混合物；组分按含量递减；每项=名称+CAS+含量+危害简述；保密组分注明商业机密但列危险性。
- **S4**：吸入/皮肤/眼睛/食入四段；眼冲≥15min；禁止催吐条件；最重要的症状和影响；对保护施救者的忠告；对医生的特别提示。
- **S5**：适用灭火剂 / 不适用灭火剂 / 特别危险性（含燃烧产物）/ 灭火注意事项及防护措施（SCBA、消防废水环保处置）。
- **S6**：人员防护措施（具体装备）/ 环境保护措施 / 收容清除方法及材料 / 防止次生灾害。
- **S7**：操作处置（通风/防静电/防火/禁配物/卫生） / 储存（温度范围/远离火种热源/禁配隔离/储区应急设备/保质期）。
- **S8**：职业接触限值（GBZ 2.1，含皮/敏/Gx标识）/ 生物限值 / 监测方法 / 工程控制 / 个体防护（呼吸/手/眼/身体）。
- **S9**：外观性状 / 气味 / pH / 熔点凝固点 / 沸点沸程 / 闪点 / 爆炸极限 / 蒸气压 / 蒸气密度 / 相对密度 / 溶解性 / 分配系数 / 自燃温度 / 分解温度 / 其他（粘度/固体含量等）；无数据写"无数据/不适用"。
- **S10**：稳定性 / 危险反应 / 应避免的条件 / 禁配物 / 危险的分解产物。
- **S11**：概述（未整体试验按组分）/ 急性毒性 / 皮肤刺激腐蚀 / 眼睛刺激腐蚀 / 呼吸或皮肤过敏 / 生殖细胞突变性 / 致癌性 / 生殖毒性 / STOT一次 / STOT反复 / 吸入危害 / 附加信息。
- **S12**：生态毒性（LC50/EC50+物种+方法）/ 持久性和降解性 / 生物累积性 / 土壤迁移性 / PBT/vPvB / 其他不良影响。
- **S13**：废弃处置方法 / 污染包装物 / 废弃注意事项；引用中国法规。
- **S14**：UN号 / 联合国运输名称 / 危险类别 / 包装组 / 海洋污染物(是/否) / 各运输方式 / 用户特殊注意事项；非危险品填"不适用"。
- **S15**：法律法规清单（现行版）+ 目录状态 + 组分法规信息。
- **S16**：编制依据 / 版本修订记录 / 缩略语 / 培训建议 / 参考文献 / 免责声明。

## 渲染样式约定
- 封面标题：黑体 18pt 居中；副题楷体 13pt。
- 一级标题（一、二、三、四）：黑体 16pt 深蓝(1F4E79)；二级：14pt；三级：12pt。
- 正文：宋体 10.5pt，行距默认，段后 2-6pt。
- 【原文问题】行用暗红 (9C2700)；【推导后的规范应写内容】黑体加粗。
- 诊断汇总表：3 列 Table Grid，表头浅蓝填充 DCE6F1。
- 页面：A4，上下 2.2cm、左右 2.5cm。
