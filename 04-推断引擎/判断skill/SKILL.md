# MSDS 规范化推导生成 (msds-inference-write)

## 用途

把"读完一份不规范 MSDS → 联网检索成分危害 → 按国标推导其他节 → 输出 Word"固化成标准流程。
每次调用本技能必须产出 Word（.docx）作为最终交付物。

## 交付约定（每次必须满足）

1. **必须产出三份 Word**：每次调用结束必须交付 `.docx`，不允许只给建议/只改表格而没产出方案文档：
   - **方案 Word**（默认）：含封面/诊断汇总表/推导依据/16节（【原文问题】+【规范应写内容】）；可写入 MSDS 的正文正常显示，仅说明内容（推导理由/编辑指令/字段提醒）用灰色楷体【说明】标出。
   - **纯 MSDS 正文 Word**（`--pure`）：只抽取"可写入 MSDS"的内容，形成一份干净可直接使用的 SDS 正文。
   - **标准写入版 Word**（`--pure` + 精简 content）：对标冠志模板的**简洁命令式**风格，每条值 1-3 短句，可直接写入标准 MSDS 表格。生成：单独写 `build_<产品>_write.py` 产出精简 content（`content_<产品>_write.json`）再 `--pure` 渲染。写法见 `rules/output_structure.md`「标准写入版」。
2. **交付位置**：`<源MSDS所在目录>\推导方案\<产品名> MSDS规范化推导方案.docx` 与 `<产品名> MSDS正文.docx`
   （例如 `F:\正式项目与模块化内容\冠志\MSDS\03-数据库\正式库\入库word  第一批\推导方案\OS-1330 MSDS规范化推导方案.docx`）
3. **质量对标**：最终 Word 的详实度与完整度对标 `templates/os1330-full-example.json`（黄金范例）：
   - 16 节**全部**要有内容，不允许缺节或仅占位；
   - 每节 = 【原文问题】+【推导后的规范应写内容】；
   - content 条目区分 msds/note（区分原则见 `rules/output_structure.md`），保证纯 MSDS 输出干净可用；
   - 含封面、诊断汇总表、推导依据、参考资料。
4. **中间产物保留**：`facts.json`（读取事实）、`content.json`（最终推导内容）留在 `推导方案/` 目录，便于复盘与打磨。

## 总流程（5 步）

### Step 0 — 输入确认
- 拿到源 MSDS 的**绝对路径**（必填）。
- 确认推导输出目录：默认在源文件同目录下 `推导方案/` 子文件夹；已存在则复用（覆盖前先确认）。

### Step 1 — 提取事实（Section 1 / 3 / 9）
```bash
python <skill>/scripts/msds_reader.py "<源MSDS.docx>" --out "<输出目录>/facts.json"
```
脚本自动：
- 兼容段落式与表格式（含合并单元格）模板；
- 归类 16 节（GB/T 16483 编号/标题识别）；
- 重点抽出 S1（产品/供应商）、S3（成分名/CAS/含量）、S9（理化项）；
- 输出 `facts.json`（供后续构建用）并在终端打印摘要，供你核对。

### Step 2 — 生成 16 节完整初稿（自动骨架，保证不缺节）
```bash
python <skill>/scripts/build_initial_content.py "<输出目录>/facts.json" \
       --product "<产品名>" [--company "<供应商>"] [--date "2026-08-14"] \
       --out "<输出目录>/content.json"
```
脚本自动：
- 生成 16 节**全部**的 content.json 初稿（S1/S3/S9 带入原 MSDS 既定事实，S3 成分自动解析并与 `rules/hazards_lib.md` 匹配标注）；
- 其余节填"待推导"占位 + 该节必填字段提示；
- 生成诊断汇总表占位（含缺失节检查与高频铁律）。

### Step 3 — 联网检索 + 逐节完善 content.json
对初稿中每节，先看该节是否需要成分危害数据（参考 `rules/hazards_lib.md` 已收录项），对未收录成分用 web search（open-websearch 技能或直接 requests）补齐：
- GHS 危险性类别与危害说明（H 码）、信号词、象形图；
- 闪点/沸点/爆炸极限等关键理化（补充 S9 缺失项）；
- 职业接触限值（**中国 GBZ 2.1 优先**，其次 ACGIH TLV）；
- 毒理学（LD50/LC50、刺激、致敏、致突变、致癌、生殖、STOT）、生态毒性（LC50/EC50）；
- 是否列入《危险化学品目录》。

然后依据 `rules/`（limits.md 判据 / hazards_lib.md 危害库 / output_structure.md 字段要求）把每节从"待推导"完善为**对标黄金范例详实度的规范内容**，写入 content.json。逐节替换占位，直到 16 节无"待推导/待精修"标记。

推导总逻辑（对应"由 1、3、9 反推其余"）：
1. **可燃性判据**：由 S9 闪点 + S3 可燃成分浓度 → 整体易燃/可燃/不燃 → 影响 S2 物理危险、S5 消防、S7 储存、S14 运输。
2. **健康危害判据**：各危险成分含量 vs 浓度限值（急性≥1%、STOT≥1%、腐蚀/刺激≥1%、过敏/致癌/生殖≥0.1%、吸入危害≥10% 且黏度条件）→ 混合物是否分类 → 影响 S2 健康危害、S4 急救、S8 接触控制、S11 毒理。
3. **环境危害判据**：水生危害成分含量（水环境≥1%）→ 支撑 H4xx → 影响 S2 环境危害、S6 泄漏、S12 生态、S13 废弃。

### Step 4 — 生成 Word（每次产出两份）
```bash
# 4a. 方案 Word（含诊断/依据/16节/参考；仅说明内容以灰色【说明】标出）
python <skill>/scripts/msds_docx.py "<输出目录>/content.json" \
       --out "<输出目录>/<产品名> MSDS规范化推导方案.docx"

# 4b. 纯 MSDS 正文 Word（只抽"可写入 MSDS"的内容，可直接使用的 SDS）
python <skill>/scripts/msds_docx.py "<输出目录>/content.json" --pure \
       --out "<输出目录>/<产品名> MSDS正文.docx"
```
**象形图实图**：用 `{"t":"pictogram","code":"GHS05"}` 形式嵌入实际图片，渲染时自动从技能
`templates/pictograms/` 取 PNG：
- **GHS 危害象形图**（9 个，S2 用）：`GHS01`~`GHS09`。按产品分类逐个列出
  （如皮肤腐蚀1B→GHS05、皮肤致敏1/急性经口4→GHS07、水生3→GHS09）。
- **TDG 运输标志**（8 类，S14 用）：`TDG1.1`/`TDG2.1`/`TDG3`/`TDG4.1`/`TDG5.1`/`TDG6.1`/`TDG8`/`TDG9`。
  危险货物运输信息按危险类别嵌入（如 UN 2735 第8类→TDG8）。
方案 Word 结构固定为：封面标题 → 任务概述与原文诊断（诊断汇总表）→ 推导依据（标准/浓度限值/产品/成分/理化/危害数据）→ 16 节逐节（原文问题 + 规范应写内容）→ 参考资料。
纯 MSDS Word（`--pure`）按**标准表格结构**渲染（对标 `PEA-4139 MSDS_CN 冠志 模板.docx` 的 16 表结构）：
封面 4 列表（产品名称/修订日期/最初编制日期/供应商/SDS编号/版本/编制依据）→ 16 节逐节 2 列表格
（表头=节标题深蓝白字，行=字段名|值，字段按 `templates/sds_structure.json` 别名匹配显示标准字段名）→
S3 成分子表 / S8 OEL 子表 / S15 法规与 S16 其他为单列表格 / S2 与 S14 嵌入象形图实图。
页眉=产品名称+SDS编号+修订日期，页脚=页码。缺项策略：S9 填"无数据"、S14 填"不适用"，其余跳过。
不出现诊断/依据/参考/说明。详见 `rules/output_structure.md`「纯 MSDS 正文的表格化渲染」。

### Step 5 — 交付核对
- **自检 16 节齐全**：用 msds_reader.py 或直接解析生成文档，确认 16 节标题都在、无"待推导"占位残留。
- **自检纯 MSDS 干净**：解析 `--pure` 生成的文档，确认无【说明】/【原文问题】/推导理由等说明性文字。
- 校验生成的 .docx 存在且非空；报告两份输出路径。
- 用不超过 5 行的中文汇报：文件路径、S1/S3/S9 核心事实、推导出的关键结论（分类/限值/法规修正）、方案+纯MSDS 两份产出路径。

## 编写 16 节时的高频铁律（违反即为原 MSDS 的常见错误，必须纠正）

| 节 | 铁律 |
|---|---|
| S1 | 必须有中英文名、供应商完整信息（含邮编/邮箱/**24h应急电话**）、推荐与限制用途、SDS编号/版本/最初编制日期 |
| S2 | 必须有紧急情况概述、GHS类别、标签要素（象形图/信号词/危险性说明/防范说明）、物理化学危险、健康危害、环境危害、其他危害 |
| S3 | 混合物按**含量递减**排序列出危险组分；保密组分要注明"名称/CAS可保密但危险性须列明" |
| S4 | 按吸入/皮肤/眼睛/食入顺序；眼睛冲洗**至少15分钟**；腐蚀/石脑油类**禁止催吐**；补症状、对施救者忠告、对医生提示 |
| S5 | 适用/不适用灭火剂 + 特别危险性（含燃烧产物） + 灭火注意事项（SCBA、消防废水环保处置） |
| S6 | 人员防护（具体装备）/环保措施/收容清除材料 + 防止次生灾害 |
| S7 | 操作（通风/防静电/防火/禁配物/卫生）+ 储存（温度范围、远离火种热源、禁配隔离、储区应急设备） |
| S8 | 职业接触限值**必须引中国 GBZ 2.1**（不得写"无可用的接触限值信息"）；含工程控制 + 个体防护（呼吸/手/眼/身体） |
| S9 | 缺项写"无数据/不适用"，不得留空；单位规范化；补气味/蒸气压/爆炸极限等标准字段 |
| S10 | 必须有：稳定性 / 危险反应 / **应避免的条件** / **禁配物** / 危险的分解产物 |
| S11 | **严禁混入与本品无关成分的毒理数据**（常见复制粘贴错误）；按实际成分逐项（急性/刺激/致敏/致突变/致癌/生殖/STOT/吸入危害） |
| S12 | 生态毒性 + 持久性降解性 + 生物累积性 + 土壤迁移性 + PBT/vPvB评估 |
| S13 | 废弃方法 + 污染包装物 + **引用中国法规**（固废法/危险废物名录），不用欧盟 EWC |
| S14 | 非危险品也要逐项填 UN号/运输名称/类别/包装组/海洋污染物（"不适用"） |
| S15 | 法规用**现行版**（如危险化学品条例→国务院令第591号，非344号旧版）；补GB 30000系列、GB 15258、职业病防治法、目录状态 |
| S16 | 编制依据、版本修订记录、缩略语、培训建议、参考文献、免责声明 |

## 输出约定
- 输出目录：`<源MSDS所在目录>/推导方案/`
- 文件名（两份）：
  - `<产品名> MSDS规范化推导方案.docx`（方案，含说明性内容）
  - `<产品名> MSDS正文.docx`（纯 MSDS，仅可写入内容）
- 中间产物：`facts.json`（读取事实）、`content.json`（推导内容，供复用/打磨）、`content.example.json`（示例模板，可复制为 content.json 起点）
- 中间产物保留在推导方案目录，方便你日后打磨技能时对比。

## 打磨提示
- 打磨主要是改 `rules/`（扩充成分危害库、修订判据）与 `templates/content.example.json`（完善输出细节），脚本一般不需改动。
- 每次打磨后在 SKILL.md 的"铁律表"或 `rules/` 中追加/修订条目，保持单一事实来源。
- 如发现某成分在检索中数据与 `hazards_lib.md` 冲突，以最新检索为准并把更新回写进 `hazards_lib.md`。

## 注意事项
1. 所有路径用绝对路径；脚本不依赖当前工作目录。
2. docx 用 python-docx 读取/生成（Anaconda 环境已装）。
3. 自动跳过 Word 锁文件 `~$*.docx`。
4. 联网检索注意网络限制：360搜索(so.com)通常可用；百度/必应/DDG 可能触发验证码，可换关键词重试或改走本地检索工具。
5. 本技能只"推导方案 + 生成 Word 方案文档"，**不直接改写源 MSDS 文件**；如需覆写源文件另按 Word 覆写模块流程执行。
