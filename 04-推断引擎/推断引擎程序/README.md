# Section 2 推断引擎程序

## 当前目标

本目录先实现 Section 2「危险性概述」的事实源整理和只读采集，不直接修改正式总型号库，也不在证据不完整时自动发布危险分类结论。

## CAS Section 2 结果库硬约束

`cas_section2_result.db` 的标准结果层只允许输出已确认的 13 个固定字段：标准名称、CAS、EC、Index No、GHS 危险性类别、象形图、信号词、危险性说明、防范说明、物理与化学危险、健康危害、环境危害、其他危害。

该层是直接供 MSDS Section 2 使用的结果层，不得写入来源、方法、证据、参考事实、适用范围、人工复核原因或其他解释性文字。没有明确标准结果时，字段值必须为 `无数据`。法规条款、来源文件、事实摘要、阈值和审核状态只能保留在证据层，不能通过刷新函数或 Web 接口进入标准结果层。

`s2_fact_package.py`、`s2_inference.py` 和 `section2_legal_source` 中的候选事实包属于推断中间层，不等同于 CAS Section 2 标准结果；只有经过标准结果写入函数校验的 13 个字段，才可以进入 CAS 结果库和 MSDS 产出链路。

当前输入链：

```text
正式中文总型号库 S1/S3/S9
          +
正式 CAS 库及型号组分关系
          +
S2 相关法规、标准、名录和规则
          ↓
S2 fact package（事实包）
          ↓
后续分类规则执行 / 人工审核 / S2 结果快照
```

## 已落地程序

- `s2_sources.json`：事实源与法规源登记清单，包含来源角色、适用范围、状态和缺口；所有已登记路径已做存在性校验。
- `s2_fact_package.py`：按唯一型号只读读取正式中文总型号库的 S1/S3/S9，合并正式 CAS 身份库的型号组分关系，并把正式库 `schema_field` 的 Section 2 骨架和 `field_mapping` 快照放入结果包。
- `s2_result_library.json`：Section 2 结果库，统一维护 GHS01~GHS09、标准名称、H/P 文案、常见物质提示和阈值参数；正式输出不直接复用原始长句。
- `s2_inference.py`：Section 2 判断条件函数，执行“闪点/初沸点 → 易燃液体类别”“CAS → 物质危害提示”“H 码 → 象形图/信号词/H/P”“含量区间 → GB/T 17519 阈值门控”等可审计条件。
- `pictogram_registry.py`：唯一象形图库通道。只允许 GHS01~GHS09 代码，并统一指向 `判断skill/templates/pictograms/` 下的红菱形 PNG；检索 GUI、覆写表单和 Word 产出共用该注册表。

运行示例：

```powershell
python .\s2_fact_package.py --model AMP-95 --out .\output\AMP-95.s2-facts.json
```

程序运行时以 `mode=ro` 打开两个 SQLite 数据库，禁止对正式库写入；空值按系统约定输出为“无数据”，同时保留原始行、单位、来源文件和页码。

## A → B 判断条件

推断不是把一份原始 MSDS 长句复制到 Section 2，而是把事实输入经过固定函数转为结果库中的标准值：

```text
S9 闪点 + 初沸点 ──(GB 30000.7-2013)──> 易燃液体类别 + H225/H226/H227 + GHS02
CAS + 物质危害提示 ──(s2_result_library)──> H 码 + GHS 象形图 + 信号词
S3 含量区间 + H 码 ──(GB/T 17519-2013)──> 达到/低于/跨越阈值
H 码集合 ──(结果映射函数)──> 简洁危险性说明 + 防范说明 + GHS01~GHS09
```

任何 CAS 未命中、含量缺失、区间跨越阈值或关键物性不完整的情形，结果保留候选值并进入 `manual_review`，不自动发布为最终分类。

## 象形图处理规则

Section 2 的“象形图”字段只接受 `GHS01`~`GHS09` 代码。GUI 选择后保存为例如 `GHS05 腐蚀；GHS07 感叹号`；覆写引擎回读代码后嵌入对应红菱形 PNG；检索 GUI 读取同一代码时直接显示同一组标准图片。`[象形图]` 和原 MSDS 内嵌的黑色符号只作为旧源文件兼容显示，不再作为新结果的图库来源。

## S2 标准输出字段

当前 `schema_field` 中 Section 2 共 11 条骨架记录，其中 2 条是分组标题、9 条是可写字段：

1. 紧急情况概述（分组标题）
2. GHS危险性类别
3. 标签要素（分组标题）
4. 象形图
5. 信号词
6. 危险性说明
7. 防范说明
8. 物理和化学危险
9. 健康危害
10. 环境危害
11. 其他危害

`字段标签`和`字段值`必须分离保存；字段标签属于固定骨架，推断程序只能生成字段值和结果证据，不能更改标准字段名。

## S2 推断所需事实

### 产品级事实

- 产品名称、中文名称、型号和产品类型；
- 产品使用建议和限制；
- 供应商和应急联系信息；
- 产品原始 MSDS 来源文件、版本和语言；
- 目标市场或适用法规范围。

### 组分级事实

- 组分名称、CAS、别名和原始表述；
- 每个组分的浓度或浓度区间；
- CAS 标准名和监管状态；
- GHS 危害类别、H 码、P 码候选；
- 危险化学品目录、重点监管、易制毒、易制爆等名录关系；
- 组分数据来源、版本和置信状态。

### 理化事实

- S9 闪点、沸点、蒸气压、密度、黏度、pH、易燃性和爆炸极限；
- 与 S2 物理危险相关的其他 S9 字段；
- 数值单位和原始值；
- 缺失、冲突和“不适用/无数据”状态。

## S2 结果生成范围

第一阶段只生成以下结果包，不直接覆写 MSDS：

```json
{
  "model": "型号",
  "input_snapshot": {"s1": {}, "s3": [], "s9": {}},
  "substance_snapshot": [],
  "applicable_regulations": [],
  "candidate_classification": [],
  "candidate_label_elements": {
    "pictograms": [],
    "signal_word": "",
    "hazard_statements": [],
    "precautionary_statements": []
  },
  "s2_fields": {},
  "evidence": [],
  "status": "manual_review"
}
```

允许的结果状态：

- `auto_pass`：事实完整、规则明确、无冲突；
- `manual_review`：需要人工确认；
- `insufficient_evidence`：关键事实缺失；
- `conflict`：来源或规则冲突；
- `not_applicable`：经适用范围判断不适用。

## S2 推断边界

1. 不根据型号名称或产品类别直接推断危险分类。
2. 不以 CAS 库存在记录作为“该物质必然具有某危险性”的唯一证据。
3. 浓度区间必须保留上下限，并区分“可能构成”和“确定构成”。
4. 不同来源的 GHS 分类、H 码、P 码出现冲突时进入人工审核。
5. S9 缺少闪点、黏度等关键事实时，不能自动否定物理危险。
6. 法规版本、目标市场和适用场景不明确时，只输出候选结果。
7. 结果包可以写入独立的推断结果库，不能覆盖中文总型号库的原始事实。
8. 只有审核通过的 S2 结果才能进入后续模板覆写。
