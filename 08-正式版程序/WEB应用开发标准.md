# Web 应用开发标准

本标准适用于 `08-正式版程序` 内所有 Web 应用。目标是让 Web 端成为既有桌面程序能力的统一入口，而不是重新复制一套业务逻辑。

## 1. 开发通道

每个 Web 应用必须经过以下通道：

1. 真实入口确认：先确认启动脚本、端口、静态资源入口和 API 入口；不得只修改未被托管的备用前端。
2. 能力复用确认：优先复用 `02-检索系统/core` 的读取、解析、检索和数据模型；Web 层只负责请求编排、状态管理和展示。
3. 页面契约：每个功能明确输入、动作、加载态、成功态、空态、失败态和恢复动作。
4. 交互验收：按用户真实路径验证“打开应用 → 执行动作 → 得到结果”，不能以接口返回 200 代替页面验收。
5. 回归验证：涉及数据库或解析器时，必须运行既有测试，并验证至少一个真实数据库查询和一个真实文件导入。

## 2. 界面要求

- 应用图标统一为圆角方形，最小可视尺寸 72×72px；图标、应用名和选中态必须具有清晰层级。
- 应用窗口遵循 Windows 桌面窗口版式：标题栏、最小化/关闭、可拖动、可调整大小、内容区独立滚动。
- 一个页面分区只承担一个主任务。导入按钮与导入后的目录分离；上传前不展示空目录占位。
- 三层数据必须使用三栏或等价的逐级导航：大类 → 型号 → Section → Section 具体内容。当前选择必须可见，内容不能与目录混在同一栏。
- 搜索框必须连接真实查询；输入、回车或点击检索都要改变结果，并显示命中数量、无结果和失败状态。

## 3. 数据与接口要求

- API 端点必须与当前正式启动入口同源，避免开发端口存在但正式入口不可用。
- 上传接口限制文件类型和大小，临时文件在请求结束后清理。
- 数据库只读浏览不得修改正式库；查询参数必须经过参数化处理。
- 返回字段至少包含稳定 ID、展示名称、来源、状态或命中信息，避免前端依赖数组位置。

## 4. 交付检查清单

- [ ] 真实启动入口已验证
- [ ] 图标与 Windows 窗口版式已验证
- [ ] 导入功能复用既有 GUI 解析链路
- [ ] 大类、型号、Section、字段逐级联动
- [ ] 型号搜索和内容关键词搜索均有真实结果
- [ ] 空结果、异常、恢复动作可用
- [ ] 既有核心测试通过
- [ ] 记录修改文件、运行入口和未验证项
