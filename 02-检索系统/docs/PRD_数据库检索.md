## 1. 项目背景

MSDS 结构读取程序是一套围绕「父子级 + 标签」结构的 MSDS 信息解析与检索系统，按 GB/T 16483 标准把 MSDS Word 文件解析为 17 节（0 页眉/页脚 + 16 标准节）三级父子级结构（节 → 大标题 → 标签 → 字段），支持全库/单文件关键词检索与批量提取。

目前系统已完成第一版 SQLite 标准字段库的建设：以 `core/schema.py` 的标准字段 Schema 为列定义基准，把 MSDS 解析结果落成四张关系表（schema_field 标准字段字典、msds_model 型号主表、msds_field 明细长表、msds_wide Schema 宽表），数据库存放于 `数据库\正式库\Data Base\msds_standard.db`，已具备 17 节 126 列宽表与完整父子级明细数据。

**当前痛点**：现有检索工具仅支持对 docx 文件实时读取后检索（导入 → 读取 → 显示 → 检索），无法直接检索数据库内已有数据。当数据量积累到数十至数百个型号时，每次检索都要重新解析 docx 既低效也无法覆盖库内全部数据。因此需要新增**数据库检索**功能，让检索工具直接面向 SQLite 库查询。

## 2. 功能定位与总体目标

数据库检索功能独立于现有的 docx 直读检索，两者并行存在、互不依赖。数据库检索只读 SQLite 库内已有数据，不涉及现场导入 docx 文件；数据入库管线（通过何种连接、何种命令写入数据）由项目后续另行确定，本功能不依赖写入方式。

功能以**产品型号作为唯一索引**，支持两类检索语义：

1. **按型号检索**：输入型号（如 PEA-4139），调出该型号在库内的完整 17 节结构数据（父子级 + 标签 + 字段值），供浏览与核对。
2. **按关键词检索**：输入任意关键词，在库内各型号的标签、字段内容、标准字段名中匹配，返回命中型号清单与命中位置（节/标签），并可进一步进入具体型号的详查视图。

检索结果的**输出格式与呈现样式完全复用现有检索工具**：GUI 端复用左侧目录树 + 右侧「徽章 | 序号 | 标签 | 字段」四列表格的样式；CLI 端复用 `--extract` 的三级父子级树文本、嵌套 JSON、扁平 TSV 三种输出格式。用户在现有工具中获得的视觉与格式一致性体验不因数据来源变化而改变。

## 3. 功能需求

### 3.1 功能独立性

数据库检索与 docx 直读检索是两个完全独立的能力，分别有各自的入口与数据视图，互不干扰：

- docx 直读检索：输入 docx 文件 → 现场解析 → 展示该文件结构（现有流程，保持不变）。
- 数据库检索：输入型号或关键词 → 查询库 → 展示库内记录（本功能，新增）。

同一型号在库内当前不存在多来源记录（一个型号一条数据），`source` 字段（docx / xlsx）保留作为数据来源追溯；若未来出现同型号多条记录，按来源分别列出，不做合并展示。

### 3.2 按型号检索（唯一索引）

- 输入框支持型号精确/模糊匹配，模糊匹配使用包含匹配（如输入「4139」可命中「PEA-4139」）。
- 命中后展示该型号的完整结构：17 节覆盖，每节按父子级展开（大标题 → 标签 → 字段值），包含总结句、成分表、子表（如 S8 生物限值）等全部内容类型。
- 展示区附带型号元信息：数据来源（docx / xlsx）、入库时间、明细行数、sha256 摘要等，便于审计追溯。
- 未命中时给出明确提示（如「库中无此型号」），并列出相近型号供参考（可选增强）。

### 3.3 按关键词检索

- 关键词检索范围为：标签（label）、字段内容（value）、标准字段名（std_name）、序号（seq），支持空格分隔多词 AND 匹配（与现有扁平检索 `search_fields` 语义一致）。
- 命中结果以「型号 → 节 → 标签」三层结构列出，保留父子级上下文；命中字段连带其节、大标题一起显示（与现有 `search_tree` 保留父子的语义一致）。
- 结果可点击/命令进入该型号的完整详查视图。

### 3.4 范围过滤

- 按型号检索与关键词检索均支持节范围过滤（如仅查 S9 物理和化学特性、或 S1、S9 多节），对应 CLI 的 `--sections 1,9` 参数。
- GUI 端在型号详查视图顶部提供节快捷选择（与现有目录树点选节一致）。

### 3.5 型号列表预览

- GUI 端数据库检索模式左侧提供**型号列表区**：列出库内全部型号（型号名 + 来源 + 明细行数），支持点选进入详查，也支持在列表内过滤（输入型号名实时过滤列表）。
- 列表为空时提示库中暂无数据，引导用户先完成入库。

### 3.6 GUI 呈现样式（复用现有范本）

GUI 数据库检索模式布局如下：

```
工具栏: [📚 库检索/单文档 模式切换] [型号/关键词输入框] [🔍 检索] [✕ 清除]
左侧:   型号列表区（全部型号，点选进入）
        └ 17 节目录树（复用 SectionTree；关键词检索过滤保留父子级）
右侧:   徽章 | 序号 | 标签 | 字段 四列表格（复用 SectionView 渲染）
        · 节标题行：深蓝通栏（跨 4 列）
        · 字段行：徽章 | 序号 | 标签（锁定） | 字段（可编辑徽章切换）
        · 总结句/通栏行：字段跨 序号+标签+字段 三列显示
        · 子表块（如 S8 生物限值）：表头 + 数据行块状渲染
        · 成分表（S3）：成分 名称/CAS/含量 表格渲染
        · S11 毒性资料：归并为 11 个国标大类行
状态栏: 型号 · 来源 · 入库时间 · 明细行数 · 检索命中提示
```

### 3.7 CLI 呈现样式（复用现有范本）

CLI 新增子命令，输出格式与现有 `--extract` 完全一致：

```
python tools/build_msds_db.py <db> --model PEA-4139              # 三级父子级树文本（同 render_tree）
python tools/build_msds_db.py <db> --model PEA-4139 --json        # 嵌套 JSON（同 render_tree_json）
python tools/build_msds_db.py <db> --model PEA-4139 --tsv         # 扁平 TSV：节|大标题|小标题|标签|字段
python tools/build_msds_db.py <db> --model PEA-4139 --sections 1,9   # 节范围过滤
python tools/build_msds_db.py <db> --model-search 关键词 [--sections 1,9]   # 关键词命中清单
python tools/build_msds_db.py <db> --models                       # 型号列表（名称/来源/行数）
```

CLI 返回码约定：成功 0；未命中型号 / 无匹配结果 1；参数错误 2。

## 4. 数据模型（SQLite 四表）

数据库 `msds_standard.db` 由四张表构成，检索功能直接消费以下结构：

### 4.1 schema_field（标准字段字典）

Schema 层定义，是宽表列定义的来源，由 `core/schema.py` 的 SECTION_SCHEMAS + _BASE_SCHEMAS 固化导出，覆盖 17 节共 132 项标准字段。

| 列 | 说明 |
|---|---|
| section | 节号 0..16 |
| seq | 标准序号（如 8.1；空 = 不固定） |
| name | 标准字段名 |
| kind | field / sub / note / comp |
| collapse | 空父级分组标签是否折叠（不产列） |
| multi | 是否可多行值（列表字段，如 S2 防范说明 P 代码） |
| in_wide | 是否生成宽表列 |
| aliases | 同义别名 JSON 数组 |

### 4.2 msds_model（型号主表）

每型号（×来源）一行，是型号唯一索引的本体。

| 列 | 说明 |
|---|---|
| model_id | 主键 |
| model | 型号（唯一索引，如 PEA-4139） |
| source | 数据来源：docx / xlsx |
| source_file | 来源文件路径 |
| sha256 | 文件摘要 |
| header / footer | 页眉/页脚原文 |
| sections_count / tables_count / fields_count / components_count / anomalies_count | 统计摘要 |
| created_at | 入库时间 |

型号取值回退链：S1 产品名称 → S0 页眉产品名称 → 文件名前缀（保证 docx/xlsx 同型号一致）。

### 4.3 msds_field（明细长表）

父子级结构全保留，是 GUI 三列表与 CLI 三级树渲染的数据源。每行一个「序号 | 标签 | 字段」，靠 (model_id, section, row_index) 还原 节 → 大标题 → 标签 → 字段 的父子级顺序。

| 列 | 说明 |
|---|---|
| id / model_id | 主键 / 外键 |
| section | 节号 |
| seq | 序号（如 8.1；空 = 无序号） |
| label | 原始标签（去序号） |
| std_name | 标准字段名（standard_name 归一化） |
| value | 字段内容 |
| kind | field（标签）/ sub（大标题）/ note（总结句）/ component（成分）/ subtable（子表） |
| editable | 可编辑标记 |
| row_index | 节内行序（父子级顺序） |
| sub_header / sub_rows | kind=subtable 时：表头 JSON / 数据行 JSON |

### 4.4 msds_wide（Schema 宽表）

每型号一行，每标准字段一列，列名 `S{节}__{标准名}`（如 S9__闪点、S8__生物限值），共 126 列覆盖 17 节。值经 standard_result 归一化归并（同义合并、多值换行连接、空值 NULL）。用于型号总览与跨型号对照视图。

## 6. 术语定义

| 术语 | 代码字段 | 含义 | 示例 |

## 7. 验收标准

1. **按型号检索**：输入库内已有型号（精确与模糊各一例）能显示完整 17 节结构，样式与现有 GUI 三列表一致；输入不存在的型号给出明确提示。
2. **关键词检索**：输入库内字段词（如「闪点」「二乙二醇」）能返回命中型号清单与节/标签位置；多词 AND 匹配正确。
3. **范围过滤**：`--sections` 过滤后仅显示指定节。
4. **型号列表**：GUI 型号列表区显示库内全部型号，点选进入详查。
5. **CLI 输出**：`--model` 文本/JSON/TSV 三种格式与 `--extract` 对应格式逐字节可比（同结构与同字段顺序）。
6. **回归**：现有 74 项 pytest 全部通过；新增数据库检索相关测试。
7. **数据完整性**：检索出的父子级、标签、总结句、成分、子表与 `docs/模板17节结构清单.md` 一致。
