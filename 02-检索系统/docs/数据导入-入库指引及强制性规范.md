# 数据导入-入库指引及强制性规范

> 适用: MSDS 标准字段库 (`数据库/正式库/Data Base/msds_standard.db`) 的批量数据清洗与入库
> 版本: v1.0 (2026-08-17, 用户确认)
> 关联: 批量检索 skill (`批量化读取/skills/msds-batch-read`) · 飞书 wiki 第 5 章 17 节清单 ·
>       定稿模板 `PEA-4139 MSDS_CN 冠志 模板.docx`

## 0. 核心原则（必须遵守）

**基于结构找内容，不是基于内容找结构。**

所有进入数据库的数据，无论原始 MSDS 长什么样，都必须遵从**已经约束好的固定父子级结构及其标签字段**：
结构（骨架）永不随数据变化，数据按结构一一对应填充；结构里没有的字段一律丢弃（写「无数据」），
**绝不扩充任何结构**。

## 1. 权威结构（三层锁定）

| 层 | 权威来源 | 说明 |
|---|---|---|
| 字段集 | 飞书 wiki「5. 父子级结构与字段（17 节完整清单）」 | 标签字段集合，清单没有的不建列 |
| 呈现结构 | 定稿模板 `PEA-4139 MSDS_CN 冠志 模板.docx` 导入检索呈现 | 父子级/顺序/层级（对照模板原 word） |
| 代码固化 | `core/schema.py` + `core/msds_db._SKELETON` + `STRUCT_FINGERPRINT` | 结构写死，入库前强制校验 |

**结构写死机制**：`build_msds_db.py` 每次运行先调 `validate_structure()` 校验结构指纹；
`schema` 字段集或骨架被人为改动 → 指纹不匹配 → **拒绝入库并报错**（返回码 3）。
批量洗数据过程中**严禁修改** `core/schema.py`、`core/msds_db.py` 的 `_SKELETON`/`_db_std_name`。

## 2. 入库流程

```powershell
# 1) 环境检查: 结构校验必须通过
python "F:\正式项目与模块化内容\冠志\MSDS\02-检索系统\tools\build_msds_db.py" <db> --models

# 2) 首次/重建: 全表重建 (清空旧数据, 谨慎)
python ...\build_msds_db.py <db> --init

# 3) 批量入库 (目录或文件清单)
python ...\build_msds_db.py <db> "<入库目录>" [--from-xlsx 透视表.xlsx]...

# 4) 验证
python ...\build_msds_db.py <db> --models                  # 型号/明细行数
python ...\build_msds_db.py <db> --model <型号> --sections 1,3,8,15   # 抽查结构
python ...\build_msds_db.py <db> --model-search 关键词      # 检索验证
```

`<db>` = `F:\正式项目与模块化内容\冠志\MSDS\03-数据库\正式库\Data Base\msds_standard.db`

## 3. 强制性规范（逐条）

### 3.1 结构层
1. **不扩结构**：17 节骨架字段是唯一的；任何原始标签不在清单 → 丢弃该行数据（写「无数据」），不新增字段/列。
2. **不改结构**：`schema.py` / `_SKELETON` / `STRUCT_FINGERPRINT` 冻结；改动=拒绝入库。
3. **统一呈现**：docx 直读检索、数据库检索、CLI `--extract` 输出必须同一骨架结构（已统一，禁止回退）。

### 3.2 数据层（骨架填充规则）
4. **父级字段列空**：`1.1 产品名称`、`1.3 供应商信息`、`2.1 紧急情况概述`、`3.2 成分`、
   `8.1 暴露控制`、`8.2 生物限值`、`0.1 页眉`、`0.2 页脚` = 父级（序号+标签，字段列留空），子字段挂其下。
5. **子表**：S3 成分 = 3 列子表（表头 成分｜CAS｜含量，每成分一行）；S8.2 生物限值 = 5 列子表
   （组分名称｜标准来源｜生物监测指标｜生物限值｜采样时间）；无数据时预留表头+空行。
6. **总结句/说明槽位（13 个）**：S11 产品说明·成分参考引导段 / S12 同 / S13 法规定义·欧盟废弃细则 /
   S15 指引段·其它的规定·符合下列法规要求·法规条目 N / S16 免责声明。
   - 内容槽：有内容显示内容，**无内容写「无数据」**。
   - S15 说明段（其它的规定/符合下列法规要求）：显示说明文字本身（跨表格列字段判定）。
7. **成分**：占位 CAS（商业机密/Trade secret）原样保留；含量占位符（>n、无数据）原样保留。
8. **归一化**：标签按 `standard_name` 归一化到清单字段（同义别名/单位括号剥离）；
   S11/S12 子项归并到大类；S15 任意法规名归并到「法规条目」。

### 3.3 检索层
9. **检索输出必须符合骨架结构**（后续按输出做匹配覆写）：GUI/CLI/批量检索的树、JSON、TSV
   全部骨架化输出（父级/子表/说明段/无数据标注一致）。
10. 入库后必须验证：型号齐全、抽查 2-3 节结构与定稿模板一致、关键词检索命中正常。

## 4. 结构变更流程（唯一合法途径）

1. 停止入库；在 `core/schema.py` / `_SKELETON` 做**有意的**结构修改
2. 重新生成指纹：`structure_fingerprint()` 的返回值 → 更新 `STRUCT_FINGERPRINT`
3. **经用户确认**后 `--init` 重建 + 重新入库
4. 同步更新：飞书第 5 章清单、`docs/模板17节结构清单.md`、批量检索 skill、本规范

> ⚠️ 任何 Agent/线程在批量洗数据时发现"某字段不在结构里" → **一律丢弃并记入审计**，
> 不得自行扩充结构或修改冻结代码。
