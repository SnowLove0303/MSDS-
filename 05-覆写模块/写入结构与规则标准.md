# 覆写写入结构与规则标准

> 模板：PEA-4139 MSDS_CN 冠志 模板.docx（定稿模板）
> 依据：`template_schema_pea4139_cn.json`（行级定位）+ `field_maps_pea4139_cn.json`（标签归一化）
> 本文件唯一职责：定义 **推导方案 → 文档** 的写入结构与规则，保证输入任何完整推导方案都能准确落位。

---

## 1 目标与约定

**输入**：用户提供的完整推导方案（JSON，标准格式见 §2）。
**输出**：按模板骨架覆写后的 MSDS 文档（16 节 + 页眉页脚结构不变）。
**铁律**（任何写入不得破坏）：

| 结构 | 规则 |
|---|---|
| 16 部分标题/编号/顺序 | 不可覆写、不可增删 |
| 模板已有字段行（序号+标签） | **固定死、不可删、不可改**；覆写一律按字段（标准标签）匹配值格 |
| 两列字段行标签格 | 保留模板原文（序号 run + 中文标签 run 双 run 格式），只写值格 |
| 多列表头（S3 成分 / S8 生物限值） | 不可覆写 |
| 节内行序 | 恒等于模板 schema 的 ri 顺序（Word 出现顺序） |
| 边框 | 新增行必须继承模板行边框模式，保证全节边框连续 |
| 值格全覆盖 | 模板字段方案未给 → 写"无数据/无"（清旧产品残留），不得保留旧值 |

## 2 推导方案标准格式

### 2.1 顶层结构

```json
{
  "meta": { "产品名称": "...", "修订日期": "...", "版本": "..." },
  "missing_policy": "no_data",
  "missing_text": "无数据",
  "sections": {
    "1": { "<标准标签>": "<值>", ... },
    "2": { ... },
    "3": { "产品类型": "...", "components": [ {...}, ... ] },
    "4": { ... }, "5": { ... }, "6": { ... }, "7": { ... },
    "8": { "呼吸系统防护": "...", "bio": [ {...} ] },
    "9": { ... },
    "10": { ... }, "11": { ... }, "12": { ... }, "13": { ... },
    "14": { ... },
    "15": { "法规列表": [ "...", "..." ] },
    "16": { "免责声明": "..." }
  }
}
```

- `meta` → 页眉页脚（S0）与首页头部
- `sections` 的键 = 节号字符串 `"1"`~`"16"`；值为该节字段值映射
- 省略某节 → 该节整体不动
- `missing_policy`（顶层，可选）：模板字段行存在、方案未给该字段时的值格处理
  - `"preserve"`（默认）= 保留模板原值
  - `"no_data"` = 值格非空（旧产品残留）→ 写 `missing_text`（默认`"无数据"`）
  - `"none"` = 同上，写 `"无"`
- `missing_text`（顶层，可选）：缺值填充文本（默认`"无数据"`）

### 2.2 字段值的三种语义

| 写法 | 语义 |
|---|---|
| 省略该键 | 模板字段行仍在 → 值格按 `missing_policy` 处理（默认写`无数据`清残留；preserve 则保留模板原值）。S11 毒理为纯值驱动节，省略恒保留模板 |
| `null` 或 `""` | 清空值格（用于新产品无该数据的残留清除） |
| 非空字符串 | 覆写值格（两列字段）或整格（单格 note 行） |

> **模板骨架固定原则**：模板已有的字段行（序号+标签）永不可删、不可改，覆写只按标准标签匹配值格；方案未覆盖的模板字段 = 无残留值格（`无数据`/`无`），方案无对应字段时才允许新增行。

### 2.3 新增字段（模板无此标准标签时）

对象写法，显式声明插入锚点：

```json
"9": {
  "熔点": { "value": "无资料", "after": "外观" }
}
```

**锚点解析（三类目标，按此顺序判定）**：
1. schema 中 field 行的标准标签（如 `外观`、`公路和铁路运输`）
2. schema 中可写 note/cont/subtitle 行的整格文本（如 S16 `免责声明` note 行、S8 手套材质 note 行）——整格可覆写行的文本可作锚点
3. 本方案中先前声明的其他新增字段名（**链式锚点**，如 S14 `联合国运输名称` after `联合国危险货物编号`，而 `联合国危险货物编号` 本身也是新增字段）——引擎须按方案键出现顺序先插入前置新增字段，再依次插入后继

- `after` / `before`：锚定相邻锚点，决定插入位置（父子级判定：锚点同父级，插入到锚点后/前）
- 无锚点 → 默认插入节末、最后一个标准字段之前（若节有"其他信息"则插其前）
- 新增行 = 克隆锚点行的表格结构，标签格改写为新标签（保留模板格式），边框按 §6 继承

### 2.4 特殊容器（数组）

| 节 | 键 | 元素结构 | 写入行为 |
|---|---|---|---|
| 3 | `components` | `{"化学品名称","CAS编号","含量%（w/w）"}` | 清空现有成分数据行后按数组逐行写入；行数=数组长度 |
| 8 | `bio` | `{"组分名称","标准来源","生物监测指标","生物限值","采样时间"}` | 同 S3：先清空子表数据行，再逐行写入（数组=空→保留表头无数据行；数组含占位行→写入占位） |
| 15 | `法规列表` | 字符串数组 | 覆写 R3 后法规条目行区域（R4~R8 按列表长度重建） |

### 2.5 新增子表（模板无该多列子表时）

对象写法，显式声明子标题+表头+数据行+插入锚点：

```json
"8": {
  "职业接触限值": {
    "subtitle": "职业接触限值：",
    "headers": ["组分名称", "标准来源", "类型", "标准值", "备注"],
    "spans": [1, 1, 1, 1, 1],
    "rows": [
      {"组分名称": "...", "标准来源": "GBZ 2.1-2019", "类型": "PC-TWA", "标准值": "未建立", "备注": "..."}
    ],
    "before": "呼吸系统防护"
  }
}
```

- `before` / `after`：锚定相邻行键（同 §2.3 三类锚点），决定子标题+表头+数据行块插入位置
- 数据行数 = `rows` 数组长度；每行元素键须与 `headers` 对应
- 子标题/表头保留模板列风格，数据行边框按 §6 继承

## 3 定位与归一化规则

写入定位走 3 步，任何一步未命中即按 §2.3 视为新增字段：

```
输入标签 → ① field_maps 归一化 → 标准标签
标准标签 → ② schema[节].rows 匹配 label 或 key
命中且 writable=true → ③ 写入值格（field）或整格（note/cont）
```

**行键名体系**（schema 每行可定位的键）：
- field 行 → `label`（如 `外观`、`公路和铁路运输`）
- 可写 note/cont/subtitle 行 → `key`（schema 已补充，如 S16 `免责声明`、S8 `手套材质_氟化橡胶FKM`、S12 `生态毒性_延续`、S15 `法规入口`）——单格整格可覆写的行纳入键名体系
- 不可写行（节标题/子标题/表头/引导行）→ 无键，不可命中

**note 行（含延续行）匹配两通道**：
1. 行文本归一化标签（如 S16 免责声明整格首行文本）
2. 语义键 `key` + startswith 前缀（`NOTE_ROW_KEYS`，如 `生态毒性_延续`→前缀`其他`）——匹配文本取标签格；**标签格为空时取值格首段**（S12 延续行标签格为空、值格以`其他：`开头）
- 语义键命中且行为两列结构（延续/注释行，如 S12 cont）→ **只操作值格**：值非空写值格并删其后延续值区，值空清空值格（标签格保留原文不动）
- 语义键命中的单格行（免责声明等）→ 整格重放

**匹配优先级**：
1. 输入标签与标准标签/note-key 完全一致（最高）
2. field_maps 映射命中（如 `嗅觉阀值→嗅觉阈值`、`相对密度→密度`、`其他危险→其他危害`）
3. 前缀匹配（唯一命中才采用，如 `pH值（5%水溶液）→pH值（1%水溶液）` 待归一化补充）
4. 链式锚点：方案内新增字段名可作后续新增字段的锚点（按方案键出现顺序逐步生效）

**父子级规则**：
- 子字段（schema 中 `parent != null`，如 1.1 下的中文名称/化学品分类）写入时必须跟随父字段（如 1.1 产品名称）所在块，不得跨父级移动
- 新增子字段 → 锚点必须取同父字段
- 无序号字段行（如 S7 安全操作防范）的先后顺序 = schema ri 顺序，输入标签自动定位

## 4 写入动作语义

| 动作 | 触发 | 执行内容 |
|---|---|---|
| `overwrite` | 命中 schema 行 + 值非空 | 写值格（field）或整格（note/cont），保留标签格双 run |
| `clear` | 命中 + 值为 `""`/`null` | 清空值格 |
| `skip` / `fill_missing` | 模板字段存在 + 键省略 | `missing_policy="no_data"`（推荐）→ 值格写`无数据`（清旧产品残留）；`"preserve"`（默认）→ 不动模板原值。S11 纯值驱动节恒保留 |
| `insert_field` | 未命中标准标签 + 有锚点/可判位 | 克隆锚点行插入，写值 |
| `rebuild_data_rows` | components/bio/法规列表 出现 | 先删数据行区，再按数组写入 |
| `delete` | prep 阶段（引擎自动，不依赖写入项） | 按残留特征前缀删除 guide 引导行（S11 R1/R2、S12 R1/R2、S13 R1，如"该产品无可用的…"/"以下为二乙二醇单丁醚…"/"必须遵守适用的国标…"） |
| `keep` | 不可覆写项 | 不产生任何写入 |

> **只增不删**：模板已有字段行（序号+标签）固定，任何覆写都不得删除或改写标签格；唯一删行通道是 prep 的引导行清理（旧产品残留，非模板标准字段）与子表 `rebuild_data_rows` 的数据行重建。

> prep 另含缺陷标签格清理：S8 手部防护标签格混入上一行值"喷涂过程中要求有呼吸防护设备。"时，先清理为纯标签`手部防护：`再匹配覆写。

## 5 逐节写入细则

- 5 字段覆写（化学稳定性/危险分解产物/可能的危害反应/应避免的条件/禁配物）

## 6 行增删与格式继承

- **新增字段行/数据行** 统一走引擎行克隆路径：克隆相邻模板行 → 改写值格/标签格 → 边框修正
- **边框模式**（模板固有）：首字段行上边框=单线下=虚线 → 内部行上下=虚线 → 末字段行下边框=单线
  - 新增块首行：上边框继承上一模板行的下边框
  - 新增块末行：下边框继承下一模板行的上边框；**下一行无实际顶线（top=nil，顶线由节标题/上邻底边提供，如 S16 免责声明紧跟节标题）时，继承其上方模板行的底边**；源边框为 nil/空视同无边框、用 fallback（single/dotted）补齐，防止断线
  - 块内相邻行：虚线
  - 模板末行被推为中间行时：其下边框由单线还原为虚线
- **删除引导行后**（S11/S12/S13）：首数据行上边框修正为与节标题底边一致
- **行数校验**：写入后行数 = 模板基数 + 新增数 - 删除数，与实际方案一致

## 7 写入校验清单（每次覆写后必检）

1. 16 节标题/编号/顺序未变
2. 模板已有字段行未删、序号/标签未改（只写值格）
3. 值格内容 = 推导方案值；占位符"此处填写…"清零
4. 新增行边框连续（首行/末行/块内三态正确）
5. 成分行数 = components 长度；生物限值行数 = bio 长度；法规行数 = 法规列表长度
6. 引导行已删、无旧产品残留文本
7. **模板字段值格全覆盖**：方案未给字段 = `无数据`/`无`（missing_policy），无旧产品值残留、无空置字段
