# field_maps 模板适配指南

## 作用

覆写引擎**以模板为主**识别/匹配/覆写字段。源文件（或检索/推断输出）的字段写法常与
模板不同（同名异写、子标题写法、名称更完整等），`field_maps.json` 负责把这些写法
**映射到模板的标准字段**——即「打标签、建通道」。

通道建好后，覆写引擎才能在模板里命中字段行，做「改」，而不是误删模板行再「新增」。

## 配置 schema

```json
{
  "_说明": "可选注释键（非数字键会被忽略）",
  "1": {
    "源字段写法": "模板标准字段写法"
  },
  "2": { ... },
  "9": { ... }
}
```

- **键**：归一化后的源字段写法（去空白 + `FIELD_ALIASES`，如 `嗅觉阀值`→`嗅觉阈值`）；
- **值**：归一化后的模板标准字段写法；
- **按节分维护**（键为节号，可写字符串 `"2"` 或数字 `2`），避免跨节误匹配。

## 新增模板的适配流程

### 第 1 步：确认模板标准字段

用结构读取检索工具读取新模板，确认各节字段的标准写法（以模板为准）：

```bash
# 结构读取 CLI 打印 16 节三级结构
python main.py --cli "新模板.docx"
```

### 第 2 步：复制默认配置，命名带模板标识

```bash
cp field_maps.json field_maps.<模板名>.json
```

### 第 3 步：按需增删映射规则

只改差异项，保留公共规则（S2 的 GHS 标准结构、S9 的别名等）。

### 第 4 步：覆写时指定配置文件

```bash
python msds_overwrite_engine.py \
  --template "新模板.docx" \
  --write-items write_items_xxx.json \
  --out "输出.docx" \
  --field-map field_maps.<模板名>.json
```

也可用内置 `SECTION_FIELD_MAP`（无 `--field-map` 时）或同目录默认 `field_maps.json`。

### 第 5 步：看日志验证通道命中

- ✅ 字段应显示为 **`改 rowN`**（复用模板行覆写）；
- ⚠️ 若显示为 **`增`**（克隆新行）且同节大量字段如此，会触发
  `S<N>: 写入项 X 个字段中 Y 个靠新增插入，与模板字段差异大，请核对字段映射/标准字段清单`
  告警 —— 说明映射未命中，需要补规则。

## 空值策略配置（顺带说明）

写入项 JSON 顶层 `empty_policy` 或 CLI `--empty-policy` 控制空值行为：

- `warn`（默认）：空值覆写清空模板 + 模板原值非空时告警；
- `overwrite`：静默清空；
- `preserve`：空值跳过，保留模板原值。

若某个模板的默认值（如信号词"警告"）是**有意义的法定值**而非占位，建议对该模板用
`preserve` 策略，避免被推断引擎的空值误清空。

## 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 字段被 `删`+`增` 而非 `改` | 映射未命中，源写法 ≠ 模板写法 | 在 field_maps 补映射 |
| keep_structure 节缺必需字段告警 | 推断引擎漏输出标准字段 | 核实该字段是否应为空值；补输出或接受模板默认 |
| 空值覆写告警（模板原值被清空） | 写入项含空值字段 | 改用 `preserve` 策略或修正写入项 |
| 成分名折断成两行 | 名称含空格 + 模板缩进/左对齐 | 引擎已自动去空格 + 居中；若仍异常检查模板单元格 |
