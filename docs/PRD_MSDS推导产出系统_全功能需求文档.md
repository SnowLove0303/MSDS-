## 1. 项目概述

### 1.1 背景与痛点

冠志（及国彩）化工企业需要持续向客户、法规机构、供应链提供符合规范的 MSDS（化学品安全技术说明书，Material Safety Data Sheet / SDS）。当前痛点：

1. **存量 MSDS 质量参差**：大量历史 MSDS 不符合 GB/T 16483-2008 / GB/T 17519-2013 规范（缺节、错位、值混入标签、缺 H/P 代码、引用过时法规等），实测 766 份文件中仅 6 份"完美合格"。
2. **人工重写成本高**：一份 MSDS 的规范重写依赖专业人员的法规知识与成分危害数据，耗时数小时。
3. **数据分散**：成分危害数据、法规原文、历史 MSDS、CAS 物质信息分散在 Excel/PDF/网页中，无统一数据库支撑。
4. **多格式产出**：同一产品需产出 中文/英文 × 冠志/国彩 × Word/PDF 多种规格，人工重复排版。
5. **推导结果不可追溯**：AI 推导缺乏"唯一事实源 + 真实源"的双源约束与过程记录。

### 1.2 项目目标

构建一个**"表单采集 → 检索诊断 → 数据库支撑 → 联网搜证 → AI 推导 → 模板覆写 → 多格式输出"**的 MSDS 全链路推导产出系统：

- **输入**：用户表单（S1/S3/S9 源头数据）或存量 MSDS 文件
- **过程**：以【事实原】（历史 MSDS/法规/CAS 库）为唯一事实源，以【真实源】（Chrome 插件搜集的权威渠道数据）为外部验证源，由 AI Agent 依据 GB/T 16483/17519 推导其余各节
- **输出**：符合规范、可追溯、多语言多模板多格式的 MSDS 成品

### 1.3 成功指标（KPI）

| 指标 | 目标 |
|---|---|
| 存量 MSDS 规范合格率 | 从 ~1% 提升至 ≥90% |
| 单份 MSDS 推导产出时长 | 从人工数小时 → AI 辅助 ≤30 分钟 |
| 推导内容可追溯率 | 100%（每条推导结论标注依据来源） |
| 多格式转换 | 1 份源 → 8 种规格（中/英 × 冠志/国彩 × Word/PDF） |
| 数据落地率 | 成分危害 / 法规 / CAS 库结构化入库 ≥95% |

```
               │
┌──────────────▼──────────────────────────────────────────────┐
│                        产出层                               │

└─────────────────────────────────────────────────────────────┘
```

### 2.1 核心概念定义

| 概念 | 定义 |
|---|---|
| **事实原（Fact Source）** | 系统内已落库的可信数据：历史 MSDS、法规原文、CAS 物质清单、成分危害库、标准模板。作为推导的**唯一事实基准**，不可被外部来源覆盖 |
| **真实源（Truth Source）** | 通过数据搜集插件从权威外部渠道（国家标准全文公开系统、生态环境部、应急管理部、NITE、ECHA、PubChem 等）实时获取的**验证性数据**，用于补充/校验事实原 |
| **标准结构范式** | 以标准字段库（Excel/JSON）定义的「节 → 父子级 → 标签」为唯一输出结构；标准库有而文件没有的字段标注「无数据」 |
| **推导依据** | 每条 AI 推导结论必须挂接的支撑：法规条款 / 浓度判据 / 危害库条目 / 检索来源 URL，形成可追溯链 |

### 3.2 模块二：检索系统（导入 MSDS → 检索与输出）

**定位**：解析任意 MSDS，按**标准结构范式**输出，支持批量检索与规范诊断。

**现状基础**：`结构读取/`（core/docx_reader.py 等，全库 646+ 文件解析 0 失败、token 级 0 遗漏）。

#### 3.2.1 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| RET-01 | MSDS 文件读取 | P0 | 支持 .docx/.doc；兼容段落式/表格式/合并单元格/VML 文本框/自动编号 |
| RET-02 | 16 节三级父子级解析 | P0 | 节 → 大标题/小标题 → 标签 → 字段（GB/T 16483 结构） |
| RET-03 | 页眉页脚 → Section 0 字段化 | P0 | 页码/版本/公司名/产品名等可编辑状态标注 |
| RET-04 | S3 成分表多形态解析 | P0 | 三列表/单列表格/列内多行/'Mixtures' 声明；全角转半角归一化 |
| RET-05 | S8.2 生物限值子表 | P1 | 组分名称/标准来源/监测指标/限值/采样时间结构化 |
| RET-06 | 关键词检索 | P0 | 树上检索保留父子级；scope: label/value/all/section；空格多词 AND；页码排除 |
| RET-07 | **标准范式输出** | P0 | **以标准字段库（父级→标签）为唯一输出范式**；标准库有而文件无 → 自动标「无数据」；同父级多值 → 自动扩列（成分1/2/3…） |
| RET-08 | 批量检索矩阵 | P0 | 多文件 → 型号×标准字段 对比矩阵（无数据黄色标注），定位需重构文件 |
| RET-09 | 规范符合性诊断 | P0 | 逐字段对照标准库：命中/缺失/多余；父子级对照；输出诊断报告 |
| RET-10 | 导出 | P0 | JSON（标准范式）/ TSV / Excel 矩阵 / Word 结构文档 |
| RET-11 | 检索不命中页码 | P1 | Section 0 页码字段不参与检索（已实现） |
| RET-12 | 标准字段库同步 | P1 | 标准库 Excel 变更 → 一键重新提取标准结构 JSON |

#### 3.2.2 标准范式输出格式（核心）

```
行1: 父级分组（合并单元格）  0.1 页眉 | 0.2 页脚 | 1.1 产品名称 | 1.3 供应商信息 ...
行2: 标签                Version | 产品名称 | 中文名称 | 化学品名称（1）| CAS编号（1）...
行3+: 数据（每文件一行）     PEA-4139 | V1.0 | ... | 无数据(黄底) | ...
```

规则：
- 标准库有、文件未检出 → `无数据`（matched=false）
- 同一父级标签多值 → 扩列 `标签(2)(3)`，成分槽 1~5+ 动态展开
- 锚点列（父级占位）不取值不标无数据
- 同义归一化：GHS象形图←象形图、危险性说明←危害性说明（schema.standard_name）

### 3.3 模块三：数据库（事实原）

**定位**：MSDS 全生命周期数据的唯一事实源，支撑检索/推导/覆写。

**现状基础**：`数据库/`（MSDS 中文/英文/冠志/国彩 分类）、`推断引擎/法规匹配库/`（法规 PDF + JSON 索引）、`结构读取/三表建库`（标准汇总表+原始表+字段映射表）。

#### 3.3.1 数据域规划

| 数据库 | 内容 | 现状 | 目标 |
|---|---|---|---|
| **MSDS 历史库** | 全部历史 MSDS 的结构化解析结果 | Excel 三表库 | SQLite 表：文件元信息 + 每字段记录（含 值/无数据/来源文件） |
| **法规库** | 法律法规/国家标准/行业标准 | 法规匹配库（PDF+JSON 索引） | SQLite：法规条目（编号/名称/现行版本/正文路径/要点摘要） |
| **CAS 物质清单库** | 物质/CAS 号/危险分类/危害数据 | 部分 JSON | SQLite：物质主档 + 危害分类 + 理化 + 毒理 + 生态 + 限值 |
| **成分危害速查库** | 常用成分 GHS 分类/限值 | hazards_lib.md | SQLite + 保留 Markdown 编辑源 |
| **标准模板库** | 冠志/国彩 × 中/英 × Word/PDF 模板 | 标准模板目录 | 模板元数据表（品牌/语言/格式/适用版本） |
| **标准字段库** | 父子级→标签 规范 | Excel.xlsx + 标准字段结构.json | 作为范式源头，双向同步 |

#### 3.3.2 核心表设计（SQLite）

```sql
-- MSDS 文件
CREATE TABLE msds_files (
  id INTEGER PRIMARY KEY,
  model TEXT,                -- 型号 (S1 产品名称)
  file_path TEXT UNIQUE,
  brand TEXT,                -- 冠志/国彩
  language TEXT,             -- 中文/英文
  sha256 TEXT,
  sections_found INTEGER,
  missing_sections TEXT,     -- 缺失节 JSON
  imported_at TEXT
);

-- MSDS 字段记录 (检索/标准范式结果)
CREATE TABLE msds_records (
  id INTEGER PRIMARY KEY,
  file_id INTEGER REFERENCES msds_files(id),
  section INTEGER,           -- 0..16
  parent TEXT,               -- 父级
  label TEXT,                -- 标签 (标准字段)
  seq TEXT,                  -- 序号
  value TEXT,                -- 字段值
  status TEXT,               -- 'matched' | '无数据' | 'anchor'
  extra_idx INTEGER DEFAULT 1,  -- 多值扩列序号
  UNIQUE(file_id, section, parent, label, extra_idx)
);

-- 法规
CREATE TABLE regulations (
  id INTEGER PRIMARY KEY,
  code TEXT,                 -- 标准/法规编号 GB/T 16483
  title TEXT,
  category TEXT,             -- 法律/行政法规/国标/行业标准/国际公约
  is_current INTEGER,        -- 是否现行有效
  doc_path TEXT,
  summary TEXT
);

-- CAS 物质
CREATE TABLE cas_substances (
  cas TEXT PRIMARY KEY,
  name_zh TEXT, name_en TEXT,
  ghs_class TEXT,            -- GHS 分类
  oel_cn TEXT,               -- 中国职业接触限值 GBZ 2.1
  ld50 TEXT, ec50 TEXT,
  hazard_statements TEXT,    -- H 码
  pictograms TEXT
);
```

### 3.5 模块五：推导引擎（AI Agent）

**定位**：基于【事实原 + 真实源】双源约束，由 AI Agent 依据 GB/T 16483-2008 / GB/T 17519-2013 从 S1/S3/S9 推导其余各节（S2、S4~S8、S10~S16）。

**现状基础**：`推断引擎/判断skill/`（msds-inference-write 技能：msds_reader → build_initial_content → 联网检索完善 → msds_docx 产出）。

#### 3.5.1 推导总逻辑（判据链）

```
S1/S3/S9 既定事实
    │
    ├─ 可燃性判据: S9 闪点 + S3 可燃成分浓度
    │     → S2 物理危险 / S5 消防 / S7 储存 / S14 运输
    ├─ 健康危害判据: 危险成分含量 vs 浓度限值
    │     (急性≥1% / STOT≥1% / 腐蚀刺激≥1% / 过敏·致癌·生殖≥0.1% / 吸入危害≥10%+黏度)
    │     → S2 健康危害 / S4 急救 / S8 接触控制 / S11 毒理
    ├─ 环境危害判据: 水生危害成分 (水环境≥1%)
    │     → S2 环境危害 / S6 泄漏 / S12 生态 / S13 废弃
    └─ 法规引用: S15 现行版法规 / S16 编制依据
```

#### 3.5.2 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| INF-01 | 事实提取 | P0 | 读取源 MSDS S1/S3/S9 → facts.json（复用检索系统解析） |
| INF-02 | 初稿骨架生成 | P0 | 16 节全量 content.json（既定事实带入 + 其余节"待推导"占位） |
| INF-03 | 联网检索补全 | P0 | 未收录成分 → web 检索 GHS 分类/H码/限值/毒理/生态/目录状态 |
| INF-04 | 双源约束 | P0 | 事实原优先，真实源校验；冲突时以事实原为准并记录差异 |
| INF-05 | 逐节推导 | P0 | 按判据链推导，每节从"待推导"完善为规范内容 |
| INF-06 | 依据标注 | P0 | 每条推导结论挂接：法规条款/浓度判据/危害库/检索URL |
| INF-07 | 16 节铁律检查 | P0 | 高频铁律表（S4 眼睛冲洗15min、S8 必引GBZ 2.1、S11 禁混入无关毒理数据等） |
| INF-08 | 浓度限值判据 | P0 | limits.md 表驱动（含区间保守/确定双策略、保密组分、黏度条件） |
| INF-09 | 成分危害速查 | P0 | hazards_lib.md 命中优先，未收录才联网 |
| INF-10 | 产出方案 Word | P0 | 封面/诊断汇总表/推导依据/16节（原文问题+规范应写内容）+ 灰色【说明】 |
| INF-11 | 产出纯 MSDS 正文 | P0 | 只抽可写入内容，标准表格结构，象形图实图嵌入 |

### 3.6 模块六：覆写模块

**定位**：基于固定 MSDS 标准结构（父子级→标签）与标准模板，将推导/表单结果覆写到模板副本，产出新 MSDS 文件。

**现状基础**：`覆写引擎/`（msds_overwrite_engine.py ~93KB、make_write_items.py、field_maps.json、模板字节级一致）。

#### 3.6.1 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| OVR-01 | 写入项解析 | P0 | 读取写入项 JSON（表单/推导产出），逐字段映射 |
| OVR-02 | 字段映射 | P0 | 写入项标签 → 模板字段（field_maps.json 别名映射，可扩展多模板） |
| OVR-03 | 模板加载 | P0 | 标准模板（PEA-4139 冠志等）字节级内化，覆写不破坏布局 |
| OVR-04 | 三态覆写操作 | P0 | update（覆写值）/ insert（新增行）/ delete（显式删除） |
| OVR-05 | 保留结构控制 | P0 | keep_structure（如 S2 保持模板结构）防止误改 |
| OVR-06 | 空值策略 | P0 | empty_policy: warn/clear/keep（模板留空/清空/保留） |
| OVR-07 | 可编辑性约束 | P0 | 序号/标签列锁定，仅字段列可覆写；固定字段（页码等）不可覆写 |
| OVR-08 | 覆写日志 | P0 | 记录每步操作（update/insert/delete, 行号, 新值） |
| OVR-09 | 覆写校验 | P1 | 输出后重读比对：标签匹配率、值一致性、结构完整性 |
| OVR-10 | S0 页眉页脚覆写 | P1 | 产品名称/型号/修订日期等可变字段 |
| OVR-11 | S3 成分表重建 | P1 | 按成分列表重建模板成分表行（含保密成分策略） |
| OVR-12 | 多模板适配 | P1 | 冠志/国彩模板 field_map 分离，可切换 |

#### 3.6.2 覆写操作语义

```json
// 写入项中的操作类型
{"seq": "9.3", "label": "pH值", "value": "7-9"}                // update: 覆写模板同标签字段
{"label": "新增字段", "value": "x", "after": "锚点"}            // insert: 在锚点后新增行
{"label": "删除字段", "delete": true}                          // delete: 删除模板行
{"label": "不可编辑字段", "editable": false}                   // 锁定: 不参与覆写
```

## 4. 端到端业务流程

### 4.1 主流程：存量 MSDS 规范化重写

```
① 检索系统: 导入存量 MSDS → 标准范式输出 → 规范诊断 (缺哪些节/字段)
      │
      ▼
② 推导引擎: 提取 S1/S3/S9 事实 → 联网检索真实源 → 依据判据推导其余节
      │        → 产出 方案Word + 纯MSDS正文 + content.json
      ▼
③ 人工确认: 逐节确认推导内容 (修改/批准)
      │
      ▼
④ 覆写模块: content → 写入项 → 套标准模板 → 新 MSDS docx
      │
      ▼
⑤ 格式转换: 中/英 × 冠志/国彩 × Word/PDF 批量产出
      │
      ▼
⑥ 校验归档: 重读比对 + 入库历史库
```

### 4.2 主流程：新产品 MSDS 创建（无存量）

```
① 表单系统: 录入 S1/S3/S9 (产品/供应商/成分/理化)
      │
      ▼
② 推导引擎: 依据表单事实 + 真实源推导 (同 4.1 ②~⑥)
```

### 4.3 支撑流程：数据建设

```
法规/CAS/成分数据 → 数据搜集插件(Chrome) 抓取 → 标准化 → 数据库(事实原)
                    → 手动录入/导入补充 → 数据库校验 → 数据版本管理
```

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 法规更新（如 GB 30000 改版） | 推导结论过时 | 法规库版本管理 + 现行版本标记 + 定期巡检 |
| 成分危害数据缺失/冲突 | 推导不准确 | 双源校验 + 人工确认环节 + 危害库持续扩充 |
| 保密成分（商业机密） | 无法完整推导 | 名称/CAS 可保密，危险性必须列明（限值判据仍生效） |
| 复杂模板格式（.doc 老格式） | 覆写失败 | 模板内化+格式降级处理；老格式先转 docx |
| AI 推导幻觉 | 编造数据 | 事实原优先 + 依据标注 + 16 节铁律检查 + 人工确认 |
| 网络检索受限 | 推导中断 | 多搜索源降级（360/so.com 等）+ 本地危害库兜底 |
